## Целевая архитектура в трёх предложениях

Домены владеют своими данными и публикуют события в общую событийную магистраль (Kafka +
Schema Registry + CDC + Flink); аналитические данные оформляются доменами как
дата-продукты в lakehouse, а не собираются центральной командой в DWH; портал
самообслуживания даёт сотруднику собрать отчёт по опубликованным продуктам в пределах
своего доступа, не содержа при этом никакой доменной логики — поэтому подключение нового
бизнес-направления не требует его доработки.

## Как решение отвечает на задачи бизнеса

| Задача бизнеса | Решение |
|---|---|
| Витрина данных, масштабируемая независимо от числа направлений | портал без доменной логики + каталог дата-продуктов: новый домен публикует продукты, портал не меняется |
| Отчёт по любым срезам в пределах уровня доступа | семантический слой + ABAC/RLS: предикаты доступа подставляются в запрос до исполнения |
| Конструирование собственных отчётов | Report Builder поверх метрик и измерений, а не поверх сырых таблиц |
| Медданные не попадают в аналитику | классификация в контракте, псевдонимизация, отсутствие физического маршрута PHI в lakehouse, сканер схем в CI |
| Интеграция новых направлений без наращивания логики в DWH | логика возвращается в домены; DWH деградирует до источника и выводится к 36 месяцу |
| Отчёты формируются часами | потоковые витрины + lakehouse с колоночным хранением: тяжёлые трансформации выполняются один раз при публикации продукта, а не при каждом запросе |
| Рост числа источников и переход к near-real-time | событийная магистраль и Flink — целевой способ подключения источника; batch остаётся частным случаем |

## Ключевые архитектурные решения

1. **Событийная магистраль вместо центральной шины.** Camel остаётся мостом
   совместимости на время миграции; целевой способ взаимодействия доменов — события.
2. **Data Mesh, а не единое озеро.** Ответственность за качество и SLA данных — у домена,
   платформа предоставляет самообслуживание.
3. **Портал без доменной логики.** Это единственный способ масштабировать витрину
   независимо от количества бизнес-направлений.
4. **PHI не покидает медицинский домен.** Ограничение реализовано технически, а не регламентом.
5. **Strangler fig для легаси.** DWH и Camel не отключаются разом: они последовательно
   теряют функции, и каждый шаг закрывается тестом на паритет.
6. **Инфраструктура как код.** Все среды описаны Terraform-модулями (Task 1) и
   разворачиваются через CI/CD с удалённым состоянием (Task 2).
